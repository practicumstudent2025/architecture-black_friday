# Архитектура MongoDB: Шардирование, Репликация и Кеширование

## Описание проекта

Данный проект демонстрирует различные варианты архитектуры MongoDB для повышения производительности и отказоустойчивости:

1. **Базовое шардирование** (`mongo-sharding`) - MongoDB с двумя шардами
2. **Шардирование + репликация** (`mongo-sharding-repl`) - MongoDB с шардированием и репликацией
3. **Полная архитектура** (`sharding-repl-cache`) - MongoDB с шардированием, репликацией и Redis кешированием
4. **Горизонтальное масштабирование** - API Gateway + Service Discovery
5. **Глобальная CDN архитектура** - CDN для статического контента

## 🚀 Быстрый старт

### Для запуска финальной реализации (sharding-repl-cache)

#### 🚀 Автоматический способ (рекомендуется):
```bash

cd sharding-repl-cache

# Запустить полную инициализацию (все автоматически)
```

**Что делает `init-all.sh`:**

- ✅ Инициализирует MongoDB шардирование и репликацию
- ✅ Заполняет базу 1000 тестовыми документами
- ✅ Проверяет работу приложения
- ✅ Тестирует Redis кеширование (измеряет производительность)
- ✅ Выводит подробный отчет о состоянии системы

#### 📋 Ручной способ (пошагово):
```bash
# Перейти в директорию с финальной реализацией
cd sharding-repl-cache

# 1. Запустить все сервисы
docker compose up -d

# 2. Проверить статус сервисов (должно быть 10 контейнеров)

# 3. ⚠️ ВАЖНО: Подождать 30-60 секунд для полной инициализации MongoDB
```

### ⚠️ Порядок выполнения:

1. **Запуск сервисов**: `docker compose up -d`
2. **Ожидание готовности**: 30-60 секунд
3. **Инициализация MongoDB**: `./scripts/init-sharding.sh` (replica sets, sharding)
4. **Заполнение данными**: `./scripts/mongo-init.sh` (создает 1000 документов)
5. **Проверка работы**: Открыть http://localhost:8080

### Проверка работы приложения

1. **Откройте браузер** и перейдите по адресу: `http://localhost:8080`
2. **Проверьте JSON ответ** - должно отображаться:

   - Количество реплик в каждом шарде
   - Информация о MongoDB топологии

### 🧪 Тестирование Redis кеширования

#### Автоматическое тестирование (в init-all.sh):
Скрипт `init-all.sh` автоматически тестирует кеширование и показывает:
- ⏱️ Время первого запроса (обычно 1+ секунд)
- ⏱️ Время повторного запроса (должно быть < 100ms)
- 🚀 Коэффициент ускорения (обычно 10-30x)
- 📊 Статистику Redis (hits/misses)

#### Ручное тестирование:
```bash
# Первый запрос (должен быть медленным ~1-2 секунды)
time curl http://localhost:8080/helloDoc/users

# Повторные запросы (должны быть быстрыми < 100ms)
time curl http://localhost:8080/helloDoc/users
time curl http://localhost:8080/helloDoc/users
```

#### Проверка Redis статистики:
```bash
# Подключиться к Redis и посмотреть статистику
docker compose exec redis redis-cli info stats | grep -E "(keyspace_hits|keyspace_misses)"
```

#### Ожидаемые результаты кеширования:
- ✅ **Первый запрос**: 1-2 секунды (загрузка из MongoDB)
- ✅ **Повторные запросы**: < 100ms (загрузка из Redis)
- ✅ **Ускорение**: 10-30x раз
- ✅ **Redis hits**: Увеличиваются при повторных запросах

## 🐛 Устранение неполадок

### Если сервисы не запускаются:
```bash
# Остановить все контейнеры
docker compose down -v

# Удалить конфликтующие контейнеры
docker rm -f $(docker ps -aq)

# Перезапустить
docker compose up -d
```

### Если MongoDB не инициализируется:
1. Убедитесь, что все контейнеры запущены: `docker compose ps`
2. Подождите 30-60 секунд для полной инициализации
3. Выполните команды инициализации из README.md

### ⚠️ Важно про скрипт mongo-init.sh:
- **НЕ запускайте** `./scripts/mongo-init.sh` до инициализации MongoDB
- Скрипт создает 1000 документов в коллекции `helloDoc` базы `somedb`
- Запускайте только ПОСЛЕ настройки replica sets и sharding
- Скрипт подключается к `mongodb1`, но в финальной версии используется `mongos`

## 📝 Дополнительная информация

### Конфигурация системы:
- **База данных**: `somedb`
- **Коллекция**: `helloDoc`
- **Ключ шардирования**: `_id` (hashed)
- **Кеширование**: Redis для эндпоинта `/helloDoc/users`
- **Docker образ**: `kazhem/pymongo_api:1.0.0`

### Доступные скрипты:
- **`./scripts/init-all.sh`** - Полная автоматическая инициализация (рекомендуется)
- **`./scripts/init-sharding.sh`** - Только инициализация MongoDB
- **`./scripts/mongo-init.sh`** - Заполнение базы тестовыми данными

### Архитектура системы:
- **Config Server**: 1 реплика (метаданные шардирования)
- **MongoDB Router (mongos)**: 1 инстанс (маршрутизация запросов)
- **Shard 1**: 3 реплики (primary + 2 secondary)
- **Shard 2**: 3 реплики (primary + 2 secondary)
- **Redis**: 1 инстанс (кеширование)
- **FastAPI**: 1 инстанс (веб-приложение)

### Производительность:
- **Без кеша**: ~1-2 секунды на запрос
- **С кешем**: ~30-50ms на запрос
- **Ускорение**: 20-40x раз
